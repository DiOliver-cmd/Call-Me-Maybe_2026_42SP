# Decode profiling (T8.3)

Generated by `uv run python -m experiments.profile_decode --output <path>`.
Times are `time.perf_counter` wall-clock on the development CPU (8 vCPU,
Python 3.14, Qwen/Qwen3-0.6B on CPU, no KV cache in the public SDK). The run
reuses the decoded-token cache at `.cache/token_text.json`.

Instrumented functions: `allowed_token_ids` (the decoder mask),
`model.encode`, `model.logits` and `model.decode`. The two cases are a real
string call (`Reverse the string 'hello'`) and a real numeric call
(`What is the sum of 2 and 3?`), decoded exactly as the pipeline does
(`NUMBER_EOS_BONUS = 25.0`).

## Cache design

`TokenizerIndex` gains a mutable, non-compared field:

```python
allowed_cache: dict[tuple[object, str], tuple[int, ...]] = field(
    default_factory=dict, compare=False, repr=False
)
```

`allowed_token_ids(dfa, index)` keys the result by
`(dfa.state, discriminator)` and stores the computed tuple on a miss. The
discriminator is chosen so the cache is transparent:

| state | discriminator | why |
| --- | --- | --- |
| `NAME_VALUE` | `dfa.name_buffer` | the mask is the set of valid name prefixes |
| `PARAM_VALUE_NUMBER` | `dfa.number_buffer` | `0` cannot take a digit, `1` can; `1.` needs a digit |
| `PARAM_VALUE_BOOLEAN` | `dfa.literal_buffer` | `t` allows `r`, `tr` allows `u` |
| `PARAM_VALUE_STRING` | `"u<n>"` while `unicode_remaining > 0` | after `\u` only hex digits fit |
| everything else | `""` | the remaining buffers cannot change the mask |

The task brief assumed value states are buffer-independent for each
`DFAState` member. Measurement shows that is false for the number, boolean and
Unicode-escape masks (`PARAM_VALUE_NUMBER` has 13 allowed ids at buffer `1` but
3 at `0`; `PARAM_VALUE_BOOLEAN` differs between `t` and `tr`;
`PARAM_VALUE_STRING` has 485/872/2428 allowed ids at `unicode_remaining`
4/3/2). Keying only by the enum would return a stale mask and let the decoder
select a token that the DFA then rejects. The discriminator above keeps one
shared entry for the truly buffer-independent string content state (the
expensive 147k-token scan) while staying exact for the small buffer-dependent
states.

Transparency was verified against the real vocabulary: for 14 prefixes covering
names, strings, numbers, booleans and Unicode escapes, every cached result was
identical to a freshly recomputed one after `allowed_cache.clear()`.

The pipeline reuses one `TokenizerIndex` across all prompts, so the cache
persists for the whole run. `encode` is called once for the prompt plus once
per fixed segment; there is no per-step prompt re-encoding.

## Remaining bottleneck

`model.logits` is the dominant cost: **92.8%** of profiled time after the
cache, at ~3.0-3.1 s per forward pass. The mask is now 7.0%, and after the
first cold string scan most mask calls are dictionary hits. Further speedups
would require fewer forward passes (KV cache, batching or speculative
techniques), which the public SDK does not expose and which are out of scope.

## Full default run

Command: `uv run python -m src` (default 17 prompts, `NUMBER_EOS_BONUS` on).

- exit code: **0**
- wall clock: **702 s** (11m42s), versus 16m54s-18m05s before the cache
- output: 17 calls in `data/output/function_calling_results.json`
- remaining breakdown: the ~3.0 s CPU `logits` forward pass is ~93% of decode
  time; the mask is ~7% and mostly cache hits. The target of <5 minutes is not
  reached, and the remaining cost is the model forward pass, not Python mask
  iteration.
